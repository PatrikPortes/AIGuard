## Dopojení vyžadující samostatné schválení

Backend se podle zadání neměnil. Aby připravené soubory fungovaly přes jeho explicitní seznam rout, musí následující krok přidat:

1. `/favicon.ico` → `public/favicon.ico` s MIME `image/x-icon`.
2. `/assets/brand/apple-touch-icon.png` → připravený PNG s MIME `image/png`.
3. HTML odpověď z `public/404.html` se skutečným statusem 404 pouze pro nenalezené GET navigace na stránky. API a asset chyby musí zachovat své dosavadní chování a bezpečnostní kontroly. Nepřesměrovávat všechny chyby na úvod, nevracet soft-404 status 200 a nezavádět plošné servírování filesystemu.

Nové varianty ilustrace registruje existující asset katalog, není nutná změna backendové logiky. Do tohoto kroku není Apple ikona ani favicon.ico na produkčním serveru dostupná; běžná PNG favicon zůstává jako fallback.

## Cloudflare Analytics / CSP — pouze zjištění a návrh

Ve veřejně načtené úvodní stránce při této kontrole není beacon ani jiný externí skript; konzole nehlásila CSP chybu. Aktuální produkční CSP obsahuje `script-src 'self'` a `connect-src 'self'`. Přímý aktuální konflikt tedy nebyl potvrzen. Pokud je v Cloudflare aktivní automatické vkládání Web Analytics, jeho externí skript s touto CSP kompatibilní není. V takovém případě vypnout automatické vložení/beacon pro tento web, nikoli rozšiřovat CSP. Serverové/edge statistiky lze zachovat. Stav přepínače uvnitř účtu nebyl v této kontrole ověřen ani změněn.

Zdroj: https://developers.cloudflare.com/web-analytics/faq/ (rozlišení edge analytics a JS beaconu, požadavky CSP).

## www — pouze zjištění a návrh

Veřejný resolver nevrátil pro `www.verimtomu.fyi` A, AAAA ani CNAME; HTTP kontrola skončila chybou překladu hostname. www se tedy aktuálně nedá používat jako alias webu.

Po samostatném schválení vytvořit pro `www` proxied CNAME na `verimtomu.fyi` a Cloudflare redirect pravidlo omezené přesně na hostname `www.verimtomu.fyi`: HTTP i HTTPS → `https://verimtomu.fyi` s původní cestou a query stringem, status 301. Ověřit TLS certifikát pro www a pravidlo na jedné vnořené adrese. Nepřidávat wildcard pravidlo pro jiné subdomény. www nepouštět do aplikace bez přesměrování; její schválený origin zůstává apex.

Zdroj: https://developers.cloudflare.com/rules/url-forwarding/ (přesměrování vyžaduje proxied DNS).
