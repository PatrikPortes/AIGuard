# Local result-image sharing

Base: dfd7c4fd59b565c4d10470f4c59fa60b1ccb03af. Feature branch: feat/result-image-sharing.

The existing sharing control prepares a 1200×1200 PNG locally before enabling the button, preserving user activation for the native share dialog. It draws approved static logo/character assets and fixed enum-derived copy only: checker type, general category, conservative next-step text, limitations and canonical tool URL. No original text, findings, identifiers, current address, query, fragment or diagnostics enter the image renderer. No new assets, dependencies, API, CSP or infrastructure changes.

Only files generated by the renderer are accepted for native attachment (private WeakSet). Caller-supplied files are ignored. With navigator.canShare({files}) support the existing native action attaches the PNG. Without support it retains text sharing/clipboard/manual behavior and provides an explicit image-download button. AbortError still stops without fallback. Card preparation errors leave the existing text flow available and show a plain-language status. Download uses a short-lived local object URL; it does not upload or persist the image in the application. Existing canonical links still open a new check, not a saved personal result; the card explicitly explains this.

Tests: 8/8 sharing unit tests PASS, existing Stage 8 browser QA 18 scenarios PASS, five category-specific PNG renders (dimensions/MIME and real File payload) PASS, explicit file-download and 320/390/1280 layout checks PASS, npm run check PASS, strict gate 16/16 PASS. Browser API and registry simulations are test fixtures; no claim of a physical iPhone/Android share-sheet test. Screenshots/PNGs were visually inspected and saved outside the Git tree in outputs/image-sharing.

Limitations: actual attachment/caption handling depends on the phone/browser/receiving application. Older browsers without the required canvas/File features retain text sharing. Perform the established native build/release checks and a physical-device sharing smoke before production release. No merge or deployment performed.

## Approved optional-caption variant

The result control includes a local canvas preview, an optional 64-character subject label and an unchecked explicit sharing checkbox. No checker input or registry name is prefilled. The unconfirmed label is excluded from the PNG; confirming it changes the locally rendered card only. Plain-text/clipboard/canonical URL sharing remains generic. Captions are bounded plain text with controls/bidi formatting removed; canvas paints text without HTML interpretation. Newer preview generation invalidates the previous file immediately so a stale confirmation cannot be downloaded/shared. Label changes require successful regeneration before buttons re-enable. Browser check asserts unconfirmed/confirmed image differences and zero outgoing POSTs. Tested 9 unit tests, 5 category renders, file payload/download/preview and layouts; strict gate/check PASS. User approved production deployment of this variant.
