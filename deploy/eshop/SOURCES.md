## Runtime and deployment
All existing public CSP rules and SEO routes remain unchanged. The production application (172.30.41.2) keeps its egress restriction: new connections only to the private relay 172.30.41.3:8080. ARES is reached through the relay route `POST /v1/registry/ares` (same bearer authentication as the AI routes). The relay accepts exactly `{"ico":"########"}` with a valid checksum, requests only the hard-coded `https://ares.gov.cz/ekonomicke-subjekty-v-be/rest/ekonomicke-subjekty/<IČO>` without redirects, with a 3.5 s upstream timeout inside the application 4 s budget, a 128 kB response limit, at most 2 concurrent and 20 upstream lookups per minute, and forwards only the displayed fields. No hostname, URL, path or protocol is accepted from the application. If the relay or ARES is unavailable the application shows NEOVĚŘENO. Activation requires redeploying the relay image (`verimtomu-ai-proxy`) with this `ai-proxy.cjs`; no new secret is needed.

ČOI checking requires no application egress. A daily host task downloads the approved CSV without receiving user URLs; the application reads `/app/data/eshop-sources/coi.json` through the existing ai-data mount. A bundled snapshot is used only when this file has not yet been installed; after 48 hours it is unverified. An invalid runtime file or failed sync never falls back to a falsely fresh bundled copy.

Install host synchronizer by creating only `/opt/verimtomu/ai-data/eshop-sources` owned by 65532:65532, mode 0755; do not change ownership of ai-data itself. Copy `scripts/sync-coi.py` to `/opt/verimtomu/eshop-sync/`, root-owned, mode 0755. Run once as UID 65532 to create `coi.json`. Install supplied service/timer in `/etc/systemd/system`, then `systemctl daemon-reload` and `systemctl enable --now coi-sync.timer`. Daily failures write metadata marking the retained snapshot unavailable. Atomic files are 0644; no keys or user data enter this directory. No new Docker mounts or public ports.

Release delivery uses the verified runtime baseline and the overlay packaging/deploy helpers. The previous application container/image remain available for rollback. No deployment of this release or timer installation has been performed as part of preparing it.
